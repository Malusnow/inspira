## Purpose

为 Inspira 开发者提供可在本地和持续集成中重复执行的工程检查，真实覆盖现有工作区的类型、公共契约与生产构建，并通过失败退出和明确的覆盖说明防止空检查被误认为质量证据。

## ADDED Requirements

### Requirement: 统一类型检查覆盖现有工作区
仓库 SHALL 提供根命令 `pnpm typecheck`，实际检查 Web、插件、公共契约和新增检查配置的类型；任一目标失败 MUST 使根命令非零退出，不得静默跳过缺少检查脚本的目标。

#### Scenario: 类型检查成功
- **WHEN** 开发者在依赖安装完成的仓库根运行 `pnpm typecheck`
- **THEN** 三个工作区及检查配置完成真实编译器检查，全部通过才返回零退出码

#### Scenario: 工作区存在类型错误
- **WHEN** 任意一个工作区的受检源码包含不符合其类型声明的赋值
- **THEN** 根命令非零退出，并报告可定位到文件的错误

### Requirement: 测试执行真实契约断言
仓库 SHALL 提供非监听的根命令 `pnpm test`，执行公共契约的有效与无效输入类型断言。类型断言 MUST 经类型编译器验证，不能仅作为运行时无操作调用执行；命令不得依赖登录、私密凭据或外部业务服务。

#### Scenario: 现有契约回归检查
- **WHEN** 执行根测试命令
- **THEN** 对当前导出的内容类型、字符串标签和单个可选工作区等实际契约执行正反例检查，并报告执行结果

#### Scenario: 断言与契约不符
- **WHEN** 一个契约类型断言被改为与实际导出类型矛盾
- **THEN** 根测试命令非零退出，报告失败断言或类型诊断

#### Scenario: 没有发现测试
- **WHEN** 配置范围内不存在可执行测试
- **THEN** 根测试命令非零退出，不将零测试报告为通过

### Requirement: 统一生产构建
仓库 SHALL 提供根命令 `pnpm build`，执行 Web 和插件的真实生产构建并验证源码导出的公共契约；公共契约无需单独运行时产物，但 MUST 明确其覆盖方式。任一必要步骤失败 MUST 使根命令非零退出。

#### Scenario: 构建完成
- **WHEN** 从没有历史生成产物的检出运行根构建命令
- **THEN** 生成可检查的 Web 生产资源和 Chrome MV3 插件生产产物，并完成公共契约类型检查

#### Scenario: 构建失败传播
- **WHEN** 任一应用生产入口引用无法解析的模块
- **THEN** 根构建命令非零退出，不因另一应用构建成功而报告整体成功

### Requirement: 干净检出与持续集成一致
CI SHALL 在 pull request 和 push 时使用明确固定的 Node 与 pnpm 版本、冻结锁文件安装，执行根 typecheck、test、build 及现有 Web lint。执行 MUST 不依赖本地缓存产物、私密凭据或外部业务服务，且不得忽略检查失败。

#### Scenario: 干净环境执行
- **WHEN** CI 从干净检出启动
- **THEN** 按锁文件安装依赖并执行所有必要检查，只有全部成功时任务成功

#### Scenario: 锁文件不匹配
- **WHEN** 包清单与锁文件不一致
- **THEN** CI 在冻结安装阶段失败，不自动修改锁文件后继续通过

#### Scenario: 检查失败
- **WHEN** 类型、测试、lint 或构建中任一必要检查失败
- **THEN** CI 任务失败，日志明确失败命令

### Requirement: 验证能力与证据如实记录
工程文档 SHALL 记录各入口、前置条件、覆盖范围与实际执行证据，明确首批契约类型测试不等于业务运行时或浏览器测试覆盖。实施验收 MUST 包含正常运行与受控错误注入的退出码证据，不得把规划文件或未执行的 CI 当作成功证据。

#### Scenario: 交付工程检查
- **WHEN** 汇报本变更实施结果
- **THEN** 提供实际执行的命令、结果及错误注入验证，分别说明本地验证与远端 CI 的执行状态，并注明尚未建立的业务测试覆盖
