## Context

动机见 [proposal.md](proposal.md)。本变更跨产品、架构、协议、设计及代理工作流，需要设计明确文档权威来源和决策边界。

本轮只读检查结果：
- 根 AGENTS.md 已有工程约束；OpenSpec 使用 spec-driven，config.yaml 尚无项目定制。
- Web 和插件仍为示例入口；contracts 定义五种 InspirationType 和 CreateInspirationInput，已有 tags?: string[]，尚无完整采集与媒体契约。
- docs/architecture.md、vitest.config.ts、.github/workflows/ci.yml 均为空。根 test 为失败占位；Web 有 dev/lint/build，插件有 dev/build/package；独立 typecheck 与业务测试入口缺失。
- PRODUCT_BRIEF 仍含收藏、旧内容回顾、Video 仅 URL、多工作区待确认；ENGINEERING_HARNESS 示例仍用 tagIds。
- 五份 HTML 原型存在。Insights 原型包含收藏数量；Landing 使用“收藏正在看的图片”措辞；Serendipity 使用静态字号和坐标，未按频度计算。
- 多数仓库文件未被 Git 跟踪；不可将所有 untracked 文件当成本任务创建或批量删除、暂存。

## Goals / Non-Goals

**Goals:** 为每类信息确定一个维护来源；用可检查的事实与状态支撑后续规划；记录已确认产品决策和后续逐项确认的问题；产出可独立审阅的文档任务。

**Non-Goals:** 本次不确定所有未来功能细节，不执行业务实现、存储采购、认证实验、测试/CI 接线或 HTML 原型改造。不创建整套尚未实现的产品主规格，也不创建平行的任务模板系统。

### 2. 决策状态与交付状态分开记录

requirements-map 的台账包含 ID、问题/结论、决策状态、来源、受影响模块、进入条件、确认或实验依据。条目可拆开，例如“视频必须上传”已确认，“选用何种存储”待决定，“大文件上传与播放”需要技术验证。

实现状态另列未实现/部分实现/已验证及证据，避免“需求已确认”被读成“功能已完成”。只有取得用户回答才将产品选择标为已确认；工程建议可以先记录，不得用超时或沉默补齐确认。

已确认决策需全部同步：
- 取消收藏字段、操作与统计；取消旧内容回顾，仅保留 Insights 统计和 Serendipity 标签到内容流程。
- 每条内容最多一个工作区，仍允许未归类，不增加多工作区关系。
- Video 必须支持文件上传，不能再设为仅链接；此前已有视频链接范围未被明确取消，不擅自删除，具体双入口交互留待设计。
- 主动重复点击保存不按 URL/内容去重；同一次操作重试沿用请求 ID 的可靠性策略来自既有工程基线，须与主动新请求明确区分。
- tags 为用户输入的字符串数组，不要求预建标签 ID；清洗、大小写与频度计数规则尚未批准。
- Serendipity 高频标签更大、更明显、更居中，点击进入相关内容；深色下采用更高对比度以维持强调。水平布局、稳定坐标、轻微漂浮、字号参数仍为建议。

### 3. 模块与路线图围绕用户流程

逻辑模块不会自动变成共享包或服务。

| 模块 | 主要流程与依赖 |
| --- | --- |
| 身份与隔离 | Web 登录、插件会话衔接；所有私人数据流程的基础 |
| 内容库 | 五种内容及创建/详情/编辑/删除；依赖身份，媒体类型依赖资产模块 |
| 媒体资产 | 图片/视频上传、图片采集转存候选、访问与清理；依赖身份及存储决策 |
| 浏览器采集 | 网页/图片/划词触发、反馈和可选补充；依赖认证、契约、内容写入 |
| 工作区与标签 | 单工作区、字符串标签的添加和变更；依赖内容及所有权 |
| 搜索与浏览 | Everything、视图、搜索含标签；依赖内容和整理数据 |
| Insights | 热力图、数量、构成、趋势；依赖统计口径 |
| Serendipity | 频度词云、选标签、相关灵感；依赖标签统计与内容查询 |
| 外观与偏好 | 模式、主色、色阶、默认视图；主题基础可先建立，设置页随后交付 |
| 展示与分发 | Landing、演示、Chrome 入口；依赖正式发布信息 |

路线图建议：有效工程检查 → 身份与 Note 创建/查看的最小闭环 → 网页保存同步 Web → 划词与图片采集 → 标签/工作区及搜索 → 图片/视频上传 → Insights 与 Serendipity → 设置、响应式与发布。每阶段都带适用状态与验证，不将用户隔离或错误反馈拖到末尾。媒体和认证风险的实验安排在依赖功能前，具体顺序按决策可用性调整。此表是规划建议，不自动创建后续 changes。

### 4. 原型保留，冲突通过索引限定适用范围

本次不修改 HTML，以免文档建设扩张为交互实现。设计索引必须标明 Insights 收藏数量失效、Landing 的收藏措辞应按“保存”理解、Serendipity 的静态坐标不代表目标算法；原型中的其他示例数值/动效也不自动成为产品要求。替换统计卡片的具体内容不自行决定。

替代方案是本次同步改造全部原型，但这会扩大当前范围且需要视觉验证，留给独立任务。

### 5. 媒体方案记录比较结果，不默认引入供应商

已有讨论推荐“客户端取得临时上传地址后直传，后端管理元数据与权限”，作为建议写入。比较 Convex Storage、私有 S3/R2，以及有转码需求时的视频服务；仅凭常见工程模式不能宣称某供应商使用率最高。

apply 编写媒体文档时重新核实并引用官方资料：
- https://docs.convex.dev/file-storage/upload-files
- https://docs.convex.dev/file-storage/serve-files
- https://docs.aws.amazon.com/AmazonS3/latest/userguide/PresignedUrlUploadObject.html
- https://www.mux.com/docs/guides/upload-files-directly

文档必须覆盖：临时上传授权、上传完成的实际文件核验和所有权绑定、原始 URL 与文件标识的区分、进度/失败/取消、孤立文件清理、删除联动、视频格式/播放/封面、访问链接的有效期及泄露后的访问语义。私有业务记录不等于文件直链私有，限制随资料更新核实。外部 URL 转存需列出内网地址访问防护、重定向、大小限制、受保护来源及 blob/data URL 风险。这里记录方案和验证清单，不执行下载实验。

### 6. 规则与工作流不重复造轮子

AGENTS 规定边界与入口；局部规则只补两端差异；config.yaml 约束规划产物和受支持操作；OpenSpec 生成技能保持原样。ENGINEERING_HARNESS 中的独立任务模板由 change 产物取代，保留纵向切片和验收思想。

不自定义 schema，不新增开发技能。与 issue-analysis 等流程相遇时使用当前明确选择的工作流，避免为同一任务重复生成多份计划。

### 7. 基线可带显式未定项交付，相关功能不能越过阻塞

本 change 交付可信文档和决策过程，不要求所有未来产品问题在同一天确定。apply 按下面的问题顺序逐项询问并记录；无回复时保留待决定，继续无关文件。不把“等待用户回答”任务误勾选为“问题已解决”。基线验收检查台账完整，后续功能验收检查其依赖问题已确认。

## Risks / Trade-offs

- [文档复制导致漂移] → 使用责任表和决策 ID 引用，公共契约只维护一份详细说明。
- [规划被误当实现] → 规格限定为文档维护和工程协作能力；归档不创建业务完成声明。
- [遗留 HTML 误导代理] → 在设计入口逐项注明失效参考；以后修改原型时同步索引。
- [媒体方案未定影响上传编码] → 保留候选比较与相关切片进入条件，不阻塞独立 Note 流程。
- [生成规则不能强制测试通过] → 配置只作为指导；有效脚本和 CI 留给 establish-engineering-checks，明确当前空文件缺口。
- [用户同时修改仓库] → apply 前重读文件并只修改列出的目标；不使用 git reset 或清理 untracked 文件作为回滚。

## Migration Plan

1. 审阅本 change 后，由新的 apply 请求启动；重新确认文件现状。
2. 建立 requirements-map 决策台账，先同步已确认行为，再逐项讨论尚未决定的问题。
3. 按责任表补文档、更新索引与规则；所有仍未实现的接口、环境配置和测试标识为目标或待验证。
4. 执行链接/内容一致性审阅、范围检查和 OpenSpec 严格校验，报告未定问题及阻塞切片。
5. 用户后续请求归档时只同步工程规格；编码 checks 和业务切片另建 change。

没有服务部署或数据迁移；如需回退，仅回退本次确定的文档差异，保留用户其他工作和问题记录。
